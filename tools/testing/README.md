# Combined payment test tools

The existing disposable PostgreSQL suite (`apps/web/scripts/pg04-financial-smoke.mjs`) applies extensions using the existing coordinator and exercises document versions/import/retry, thirteen real matcher scenarios, refund caps, tenant pagination, private-upload orphan recovery, privacy authority/evidence and raw retention holds. These are synthetic database cases, not provider evidence. New extension cases have not been executed locally.

`receipt-load.mjs private-fixtures.json planned.json plan` validates private fixtures and writes an **unexecuted plan**. `run` requires `BRIOFOLD_ALLOW_SANDBOX_LOAD=true` and `BRIOFOLD_LOAD_SANDBOX_ORIGIN` exactly matching the configured origin. It runs the specified 25-workspace 50 receipts/sec for 15 minutes, then 200/sec for 60 seconds. The private file supplies an already enrolled P-256 device per lane: workspace_id, enrollment_id, private_key_pem, source, binding, kind, evidence_template and unused sequence_start. Templates must carry unique `%REF%` and original `%TIME%` placeholders using the fixture parser's Dhaka second layout. Store fixture keys outside Git; only use dedicated sandbox accounts. The receiving accounts and immutable attempts must already exist for the desired receipt fixture stream. This generator does not invent enrolments, orders or paid state.

The report measures **durable ingress acknowledgements**, not payment verification. `observe-load.mjs actual-load.json worker-report.json` uses `BRIOFOLD_LOAD_OBSERVER_DATABASE_URL`, checks the database is sandbox and reads actual matcher results. Missing, unparsed, unmatched, duplicate or unprocessed observations prevent its verification target PASS. This is intentionally stricter than a fast HTTP 202. The non-provider API p95 target requires its own authenticated read test. These tools are source only; no performance result is claimed.

Run the combined source, database, browser, failure and live device suites against one reviewed commit before a single deployment. Real consented Android/source receipts, merchant consumers, storage scanning, mail, connector accounts, backup restore and actual observed cohort days remain separate evidence gates. Do not use load tools on production or retain private keys in reports.

`read-load.mjs private-read-fixtures.json output.json plan|run` supplies the separate authenticated non-provider read target. It requires 25 dedicated sandbox workspaces with `read_key`, applies the same explicit sandbox origin/run authorization, and records real status/response-shape/latency at 50 reads/sec for 60 seconds over payments, customer/invoice lists, refunds and statements. Every response and zero dropped requests are required for p95 <500ms PASS. It has syntax checks only; no load run has occurred. Fixture credentials never enter the output.
