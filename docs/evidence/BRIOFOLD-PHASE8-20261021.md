## Domain and authorization

Migration 0141 is additive and control-only, requires 0140, and never changes financial balances, allocations, receipt matching, invoice authority or money movement. All commerce tables enforce FORCE RLS without raw runtime/projection grants. Narrow security-definer functions recheck current membership, disabled users, business, realm and roles. Mutations serialize per business, compare revisions and bind idempotency keys to canonical payload fingerprints. Audit events and stock movements reject update/delete.

- Products: description, size chart, active variants, SKU, barcode, option values, exact paisa prices and up to ten ordered private JPEG/PNG photos. Uploads reuse existing content validation, malware scanner and private object transport; missing scanning/storage fails closed. Images are accessed only after scoped authorization.
- Warehouses/inventory: opening stock, reasoned adjustments, atomic transfers, available/on-hand/reserved values and immutable movements. Stock constraints prohibit negative availability. Confirmation reserves once, hold/cancel releases once, shipping consumes reserved stock once, and inspected returns restock only sellable units.
- Orders: manual, scoped API and conversation-backed sources; list/board/source/state filters, detail, price snapshots, recipient/address, warehouse, item quantities, packing notes, revision-checked draft/hold correction before financial/shipping links, previous-line/total audit snapshots, exact server totals, explicit transitions, per-row bulk outcomes, bounded page exports and durable history. Standalone payment requests never become orders automatically.
- Existing Inbox free-text orders enter the central review queue. Original text/status remains separately traceable; historical `ok` never becomes verified payment or shipped stock. Recipient and structured catalog lines must be reviewed before fulfillment. Legacy source records remain accessible. Out-of-range historical amounts remain in the original source rather than being truncated.
- Coupons: fixed paisa, percent basis points with floor rounding, free shipping, expiry/start/minimum/cap/audience and total/per-customer limits. Limits are claimed atomically on confirmation, retained on shipment and released on cancellation/hold. Referenced coupon terms do not silently change.
- Financial links: Go reauthorizes and reads the original payment/invoice/refund source in the appropriate financial realm. Only verified BDT payment amounts can be linked; caller amounts are replaced by source truth. Full-source uniqueness prevents counting one payment on multiple orders; multiple partial payments cannot exceed the order total. COD settlement remains an operational receipt, never a verified gateway payment. Additional gateway payments require resolving any conflicting booked courier COD first. Refund cases and exchange orders are explicitly separate operations.
- Delivery: shipment preparation, explicit manual consignment/tracking entry, packing label/order-slip printing, Code 39 order ID, hardware-scanner search, booking reconciliation, handover receipt, courier status and separate COD receipts. Manual workflows support the merchant's chosen courier without pretending to call an unsupported API.
- Steadfast adapter: encrypted per-business credentials, fixed official HTTPS API origin, exact BDT formatting, unique stable invoice, persisted booking boundary before POST, and no automatic resend after timeout/process death. Unknown outcomes must reconcile with the provider. Status lookup records provider status separately from merchant/order/payment truth. Sandbox cannot place a real consignment.
- Returns/exchanges: request/approve/reject/inspect, bounded cumulative quantities, sellable/damaged split, explicit restocking and separate draft exchange link. Approval does not send a refund or charge an exchange.
- Import/sync: RFC-style CSV and bounded first-worksheet XLSX, formula/entity/macro/link refusal, integer prices and duplicate SKU limits. Up to 500 rows per reviewed diff, explicit group variants, stale revision refusal and atomic apply. Existing stock is never replaced by imported quantities. WooCommerce uses encrypted credentials, HTTPS/DNS pinning/no redirects or proxy inheritance, paginated read-only catalog fetch, verified BDT store currency and explicit preview/apply. Missing currency/pagination proof or any non-BDT currency fails closed rather than relabeling prices. Unsupported remote types/oversized variation batches fail explicitly; no rows are silently dropped. Remote photos are not fetched around the private-media scan boundary.
- Post/image mapping: connected-business Messenger/Instagram source validation, product associations, correction/removal.
- Notifications: durable business/realm status events with independent per-member read cursors. Team notifications are distinct from customer marketing/transactional provider sends.

## Web and API

Canonical locale-neutral `/orders`, `/orders/products`, `/orders/inventory`, `/orders/delivery`, `/orders/returns`, `/orders/coupons` work in every enabled business mode. Existing shell/design tokens, nine primary entries and financial routes are preserved. Server-selected-business guards cover all commerce proxy reads/writes; no visible locale prefix or realm picker was added. SSR supplies authorized initial data; unavailable sources remain explicit errors. Forms retain drafts through errors, participate in navigation guards, and preserve uncertain idempotent commands across reload for at most thirty minutes. Credentials/file bytes are excluded from browser operation storage.

`POST /v1/commerce/orders?environment=live` (or sandbox), `orders:write`, UUID `Idempotency-Key`: reference, warehouse_id, optional customer_id, recipient name/phone/address, lines of variant_id/quantity, optional shipping_minor/coupon/notes. Returns id/saved. Caller source/price/paid/status claims are rejected. `GET` uses `orders:read`, optional item/cursor/q. Existing payment-key authority remains unchanged for financial scopes; OpenAPI and generated clients include these operational methods/scopes.
